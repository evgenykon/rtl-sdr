# RTL-SDR Обсерватория

Веб-инструмент для исследования радиоэфира с RTL-SDR на macOS: спектр, водопад, сканер частот и прослушивание FM/AM/NFM в браузере.

## Архитектура

```
┌─────────────── macOS (хост) ───────────────┐   ┌────────── Docker ──────────┐
│ RTL-SDR (USB) ── librtlsdr ── rtl_tcp ─────┼──▶│ backend (Node/TS)          │
│   (агент в тулбаре: иконка + «Выход»)      │   │  ├─ rtlTcpClient → I/Q     │
│                                           │   │  ├─ FFT → спектр/водопад   │
│                                           │   │  ├─ демод FM/AM/NFM → PCM  │
│                                           │   │  └─ сканер диапазонов      │
│                                           │   │ frontend (React/Vite)      │
└───────────────────────────────────────────┘   └────────────────────────────┘
```

- **Драйвер**: `brew install rtl-sdr` → `rtl_tcp` (поток I/Q по TCP). macOS не требует kernel-драйвера.
- **Агент** (`agent/`): Swift menu bar app — иконка в тулбаре, когда rtl_tcp запущен, контекстное меню с пунктом **«Выход»**. Запускает/перезапускает `rtl_tcp -a 127.0.0.1 -p 1234`, останавливает при выходе.
- **Веб** (`docker-compose.yml`): весь веб-стек в контейнере, бэкенд подключается к rtl_tcp через `host.docker.internal:1234`.

## Как понять, что устройство определилось

- **Агент (тулбар)**: клик по иконке → мини-окно. Строка «Устройство: ● …» зелёная — девайс найден (и rtl_tcp стартует автоматически), красная — не найден, подключите по USB. Агент проверяет устройство каждые 5 секунд (`rtl_test -t`, когда rtl_tcp не занят) и сам запускает rtl_tcp, как только девайс появляется.
- **Кнопка «Подключить»** в мини-окне запускает rtl_tcp вручную (после остановки), «Отключить» — останавливает. Там же: «Перезапустить», «Открыть веб-интерфейс», «Выход».
- **Веб-интерфейс**: зелёная точка слева от названия тюнера (например `R820T`) — rtl_tcp подключён и идёт поток данных; красная — недоступен.
- **Терминал**: `rtl_test -t` → «Found 1 device(s)» / «No supported devices found».

## Быстрый старт

```bash
./scripts/setup.sh        # brew install rtl-sdr + проверка устройства (подключите RTL-SDR)
cd agent && make app      # собрать RTLSdrAgent.app (иконка в тулбаре)
open agent/dist/RTLSdrAgent.app
./scripts/dev.sh          # docker compose up --build → http://localhost:8080
```

## Разработка без Docker

```bash
# терминал 1 — бэкенд (rtl_tcp должен быть запущен, напр. агентом)
cd backend && npm install && npm run dev

# терминал 2 — фронтенд (vite проксирует /api и /ws на :8080)
cd frontend && npm install && npm run dev
# открыть http://localhost:5173
```

## Возможности

- **Спектр** — живой FFT, сетка частот, маркер центра.
- **Водопад** — история спектра (цвет = уровень).
- **Тюнер** — частота (кГц), шаг ±12.5 кГц, пресеты диапазонов: FM 87.5–108, авиа 118–137 (AM), NOAA 162.4–162.55, 2м 144–148, 70см 430–440, PMR 446.
- **Прослушивание** — FM / NFM / AM, Web Audio API, 48 кГц.
- **Сканер** — свип по диапазону (шаг = половина полосы приёма, FFT-детекция пиков) → таблица сигналов (частота, уровень, полоса); клик по строке — тюнинг.
- **Управление** — частота дискретизации (1.024–3.2 MS/s), AGC, ручное усиление.

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/api/device` | статус устройства |
| POST | `/api/tune` | `{frequency, sampleRate?, gainMode?, gain?, agc?}` |
| POST | `/api/mode` | `{mode: fm\|nfm\|am}` |
| POST | `/api/listen` | `{on: boolean}` |
| POST | `/api/scan` | `{start, stop, threshold?}` → результаты |
| POST | `/api/scan/cancel` | отмена скана |
| WS | `/ws` | фреймы: `0x01` спектр (Float32 dB), `0x02` аудио (Float32 PCM), JSON-сообщения статуса/прогресса/результатов |

## Примечания

- Если устройство **RTL-SDR Blog V4** — нужна версия rtl-sdr ≥ 2.0 (`brew upgrade rtl-sdr`).
- Диапазон приёма типичного RTL-SDR: ~24 МГц – 1.7 ГГц (без модификаций, напрямую).
- Прослушивание радиоэфира в большинстве стран разрешено; проверяйте местное законодательство.
